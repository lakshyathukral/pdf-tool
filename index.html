        How this tool handles your documents

        Web tools that edit PDFs almost always work by uploading your file to a server, processing it there and sending it back. That means your document sits on someone else's computer, at least briefly, and you are trusting their retention policy, their staff and their security.

        This tool has no server component at all. Your documents are never sent anywhere. Like any website, we do count visits — see What we know about you below, which is a deliberately short list.

        What actually happens when you open a file

        1. Your browser downloads the application once — some HTML, JavaScript and CSS. After that, nothing further is fetched in order to work on a document.
        2. Choosing a file hands the page a reference to it through the browser's own file-picker. The bytes are read into memory with the standard File.arrayBuffer() call — the same mechanism an image viewer uses.
        3. pdf.js parses the document. It runs on a Web Worker, a second thread inside your browser, so a large file does not freeze the interface. Pages are drawn onto a <canvas> element to produce what you see.
        4. Edits change a plain data structure in memory — which page goes where, what is written on it. Your original file is never modified.
        5. pdf-lib assembles a new PDF as raw bytes, still in memory.
        6. Saving wraps those bytes in a Blob and hands them to the browser's download mechanism via an object URL — an address that exists only inside this tab and is meaningless anywhere else. No request is made.

        How you can check this yourself

        • Turn off your internet after the page loads. Every feature keeps working. Nothing that talks to a server could.
        • Open your browser's developer tools and watch the Network tab. Load a PDF, edit it, save it. You will see the page itself load, and a small analytics ping counting the visit. You will not see a request carrying your document, because none is made.
        • Read the source. The whole thing is public at github.com/lakshyathukral/pdf-tool.

        What is stored on your device

        Only your settings — watermark text, numbering format, saved presets — kept in this browser's local storage. No document, no page, no filename. Clearing your browser data removes it.

        What we know about you

        The same things any website's logs record: that a visit happened, roughly which country it came from, which page was opened, and which site linked here. Enough to know whether anyone is using this. This is measured by Cloudflare Web Analytics, which sets no cookies, stores no identifier on your device, and cannot follow you to other sites.

        What we cannot know, because it never reaches us: which documents you opened, their names, their contents, their length, or what you did to them. That is not a policy we could change our minds about — the information does not leave your browser in the first place.

        What this does not protect against

        Being honest about the limits, because a security claim that overstates itself is worse than none:

        • It does not protect against a compromised computer, a malicious browser extension, or someone with access to your screen. Anything running on your device can see what your browser is doing.
        • Once you save a file, ordinary care applies — this tool has no say in where it goes next.
        • Redaction removes text by rendering the page to an image, which is genuinely irreversible, but it does not remove attachments or every trace of document structure. Check important redactions before sending.
        • A signature image or a watermark is a picture. Neither is a cryptographic signature, and neither makes a document tamper-proof.

        Drag a box where the signature should go — its height follows the image's own proportions. This adds a picture to the page; it is not a digital signature and proves nothing about who signed.

        Redact

        Drag a box over anything that must be removed. The page is re-rendered as an image with the boxes burned in, so the text underneath is destroyed rather than covered up. Redacted pages stop being searchable.
